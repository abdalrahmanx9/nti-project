1.0

System Overview & Architecture Principles

The NTI DevOps Final Project implements an enterprise-grade, cloud-native microservice architecture designed for high availability, automated security enforcement, zero-downtime continuous deployment, and deep observability.

  • Separation of CI and CD: Jenkins is strictly responsible for code integration, automated unit testing with code coverage, quality gate enforcement, vulnerability scanning, and updating the GitOps repository. Jenkins has zero direct access or credentials to the Kubernetes cluster.
  • GitOps as Single Source of Truth: ArgoCD operates inside the EKS cluster, continuously monitoring the dedicated nti-devops-gitops repository for Helm manifest changes. ArgoCD reconciles desired Git state with live Kubernetes state, providing automated drift detection and self-healing.
  • Multi-AZ Redundancy: Microservices and databases are distributed across AWS Availability Zones (us-east-1a and us-east-1b) with Pod Anti-Affinity rules ensuring survivability against datacenter-level failures.

3.0

Automated CI Pipeline (Jenkins Multi-Branch)

Every code commit pushed to GitHub automatically triggers the Jenkins pipeline executing 7 rigorous quality and security stages:

  1. Stage 1: Checkout SCM — Clones git repository commit with SHA verification.
  2. Stage 2: Static Code Analysis & Pytest — Runs ruff code linter and executes unit tests with pytest --cov code coverage report.
  3. Stage 3: SonarQube Quality Gate — Scans Python code for security hotspots, bugs, and code smells.
  4. Stage 4: Docker Multi-Stage Build — Builds lightweight, non-root production container images tagged with ${BUILD_NUMBER}-${GIT_COMMIT.take(7)}.
  5. Stage 5: Trivy Security Scan — Halts pipeline on HIGH or CRITICAL CVE vulnerabilities in OS packages or Python libraries.
  6. Stage 6: AWS ECR Push — Authenticates with AWS ECR using IAM and pushes versioned image tags to 270485099284.dkr.ecr.us-east-1.amazonaws.com/nti-devops-app.
  7. Stage 7: Automated GitOps Push — Clones nti-devops-gitops, updates image.tag in values.yaml, and commits with authenticated credentials back to GitHub.
4.0

Continuous Delivery & GitOps Engine (ArgoCD & Helm)

ArgoCD monitors the declarative Helm chart repository (charts/nti-app) and deploys changes to the EKS cluster with zero downtime:

  • Automated Sync Policy: ArgoCD polls the GitOps repository every 3 minutes (or receives webhook) and triggers declarative reconciliation.
  • Self-Healing & Drift Correction: Manual changes applied with kubectl are automatically detected and overwritten to match the version in Git.
  • Rolling Updates: Kubernetes RollingUpdate strategy ensures 100% service availability with zero dropped requests during new container rollouts.
5.0

Application Architecture, Security & Downward API

The backend application is built using Python FastAPI and Uvicorn with deep Kubernetes runtime introspection:

  • Downward API Injection: The Kubernetes Downward API exposes spec.nodeName, status.podIP, and metadata.name as environment variables to the container for real-time telemetry display.
  • Container Hardening: Runs as non-root user (UID 1000), drops ALL Linux capabilities, and mounts read-only root where applicable.
  • Asset Versioning & Cache-Busting: Computes MD5 content hashes of CSS/JS assets at runtime (?v=ff7a9a4e62), guaranteeing zero cache lag across Cloudflare CDN edge nodes.
6.0

Observability, Telemetry & Alertmanager Alarms

Full-spectrum observability is achieved using the kube-prometheus-stack:

  • Prometheus ServiceMonitor: Automatically discovers application pods and scrapes /metrics (HTTP request counters, duration histograms, DB connection status) every 15 seconds.
  • Alertmanager Notifications: Configured with alarm rules that trigger when pod CPU or memory exceeds 80%. Automatically routes notifications via Gmail SMTP to d7oom.ahmed99922@gmail.com.
  • Grafana Dashboards: Pre-configured dashboards monitoring cluster compute saturation, pod restarts, and PostgreSQL query performance.
